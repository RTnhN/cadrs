# Kernel performance against OCCT

Generated by `tools/kernel_perf.py`; don't edit by hand. Re-run it after kernel changes that
matter for speed.

Measured 2026-10-21 on AMD Ryzen 5 7600X 6-Core Processor (12 threads), native kernel at `5c0b53e`
plus the working tree, OCCT 7.8.0 (static, `-O2`). Load average while measuring: native kernel
15–38, OCCT 11–17 (other jobs share the machine; hence CPU time).

The `occt_blend` and `smlib_fillet` rows were measured again on 2026-10-22 on the same machine
(load average 4–7) at kernel-perf `eff4843` with the fillet work through fa17; the other rows
are the run above's.

**How.** A case is a DRAW-like script both sides read: `kernel_bench` (an example of the
crate) for the native kernel, `tools/occt_bench` for OCCT, each command mapped onto the
same DRAW/OCCT calls on the same input files. Only its marked lines (the operation, not
loading its input) are timed. Each case runs in its own process, at least 5 times and
until its runs have taken a second (fewer when one run is slow). **Time is CPU time**
(user + system, all threads; the mean over the runs) on one thread: `RAYON_NUM_THREADS=1`
for the native kernel, OCCT's default (no parallel mode, as DRAW). The `mt` column is the
native kernel's median wall time on rayon's default pool (12 threads, under the
load above). Ratio = native / OCCT; times under 0.05 ms count as 0.05 ms in it.
Only cases both kernels complete enter the means; the others are listed with their error.

**The categories.**
- `occt_<group>`: OCCT's own DRAW cases (`tests/<group>`) that pass on the native kernel, as the
  generated suites run them; the operation timed (`bcut`, `blend`, `mkoffset`, `offsetperform`,
  `pipe`/`buildsweep`, `depouille`). Booleans and 2D offsets are sampled (every 12th, every 4th).
- `smlib_<suite>`: SMLib's fillet, boolean and offset cases that pass. OCCT reads the models as STEP
  the native kernel wrote, the fillet's edges picked by their middle points; OCCT's own failures
  are listed below.
- `tess`, `mass`: the largest SMLib models; the chord is 0.001 of the bounding box's diagonal, the
  angle 0.5 rad. OCCT's default mass properties (fixed Gauss rules) are fast but coarse (1e-3 off in
  volume on the blade hubs, 7e-5 on the vases); `mass_eps9` times OCCT adaptive to 1e-9, the
  native kernel's precision class.
- `step_read`, `step_write`: files of OCCT's dataset, read into bodies, and written back.

Conformance compares whole tests: the native kernel's CPU time for a process running the one
test (one rayon thread, less an empty run's) with the same tests' times on the former OCCT
backend (`bench/occt_conformance_times.txt`, wall times to 1 ms). They include the tests'
own checks (mass properties and meshes at 0.01 mm), not only the modelling operations.
